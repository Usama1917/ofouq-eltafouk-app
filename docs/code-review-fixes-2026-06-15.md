## ⚠️ خطوات نشر إلزامية (يقوم بها فريق التشغيل)

1. **تطبيق تغييرات قاعدة البيانات — إلزامي قبل/مع النشر:**
   ```bash
   pnpm --filter @workspace/db run push
   ```
   أُضيفت أعمدة جديدة (`conversations.user_id`، `users.token_version`) وفهارس كثيرة. **الكود الجديد يعتمد عليها — لو اتنشر الكود من غير ما يتعمل push، تسجيل الدخول ومساعد الذكاء سيتعطّلان** (أعمدة غير موجودة). كل التغييرات إضافية (أعمدة nullable + فهارس) فآمنة على البيانات الحالية.
   **ملاحظة (B-29):** أعمدة التوقيت حُوّلت إلى `timestamptz`؛ التحويل يفترض أن قاعدة البيانات تعمل بتوقيت **UTC** (وهو الوضع الشائع والموصى به). نُفّذ دلوقتي والبيانات لسه صغيرة = أأمن وقت.

2. **ضبط `AUTH_SECRET`:** السيرفر دلوقتي **يرفض الإقلاع** لو `AUTH_SECRET` ناقص أو قصير (<32 حرف) أو يساوي المفتاح الافتراضي، إلا لو `NODE_ENV` = `development`/`test` صراحةً. تأكّد إن `AUTH_SECRET` مضبوط بقيمة عشوائية طويلة في الإنتاج (B-06).

3. **مجمّع الاتصالات:** الافتراضي بقى 30. للإنتاج، اضبط `DATABASE_POOL_MAX` صراحةً وضع PgBouncer قدام قاعدة البيانات (B-08).

4. **حد المعدّل متعدد النسخ:** لو هتشغّل أكتر من نسخة من السيرفر، حد المعدّل الحالي في الذاكرة (per-process). يُنصح بمتجر مشترك (Redis) لاحقًا.

## ✅ ما تم تنفيذه (62 بندًا)

### الأمان (باك إند)
- **B-01** قفل مساعد الذكاء بالكامل: تحقّق هوية إجباري + ربط كل محادثة بـ`userId` + فلترة كل الاستعلامات بصاحبها + حد طلبات لكل مستخدم.
- **B-02** نسخة توكن (`token_version`) + `POST /auth/logout` + `POST /auth/change-password` يبطّلان كل الجلسات القديمة (مع توافق عكسي للتوكنات القديمة).
- **B-03** مجلد `uploads/subscription-codes` خلف تسجيل دخول + `dotfiles: deny` + `index: false`.

- **B-07** حد طول رسالة الذكاء (4000) + حد عدد رسائل التاريخ المرسلة (20).
- **B-20** رسالة تعارض تسجيل عامة (منع تعداد الحسابات).
- **B-21** حد أدنى لكلمة السر (8 أحرف) في التسجيل وتغيير كلمة السر.
- **B-22** حد معدّل صارم على رفع الصورة العامة.
- **B-23** مقارنة كلمة السر القديمة ثابتة الزمن.
- **B-25** `resolvedBy` للبلاغات من الفاعل المتحقّق لا من جسم الطلب.
- **B-38** إطار خطأ SSE + إغلاق الاتصال عند فشل بثّ الذكاء.
